# v2.36 — APP Dialer 持久化缓存

新增 APP Dialer 已装应用的**持久化缓存**，根治「很久不打开再读很慢」的问题。

## 核心改进

- **缓存落盘（Room）**：把原先仅存在于进程内存的缓存升级为写入手机存储。进程被杀、隔很久再打开拨号盘，直接读盘秒显，不再逐个读取已装应用、提取图标与名称、计算拼音。
- **自动刷新**：监听系统的「安装 / 卸载 / 更新应用」广播，去抖后自动重建缓存。新装的 App 立刻可见、卸载的不残留，无需手动干预。
- **设置页新增「缓存管理」区块**（APP Dialer 设置页内）：
  - **启用 APP Dialer 缓存**：总开关。关闭即不再读写磁盘缓存（每次实时读取），并在关闭时自动清除已落盘的缓存。
  - **更新缓存**：手动全量重建并写盘。
  - **清除缓存**：删除已缓存的应用图标与名称（带二次确认，防误触）。
- **图标包联动**：缓存记录生成时的图标包 id，切换图标包后会自动判定失效并重建刷新，保证图标是最新样式。

## 缓存了什么

| 数据 | 说明 |
| --- | --- |
| 包名 / Activity | 启动应用所需 |
| 应用名称 | 显示用 |
| 拼音全拼 / 首字母 / 小写名 | 搜索匹配键 |
| 图标位图 | 以 PNG 字节落盘，打开即秒显，免去实时取图标 |
| 图标包 id | 用于判断缓存是否因换包而失效 |

## 使用建议

1. 首次打开 APP Dialer 会后台创建一次缓存（那一次稍慢属正常）。
2. 之后即使关闭 App 进程、隔很久再开，也应**秒显**列表。
3. 安装或卸载一个 App 后，拨号盘列表会**自动反映**，无需手动「更新缓存」。
4. 若切换了全局图标包，首次打开拨号盘会自动重建缓存以刷新图标。

## 已知说明

- 缓存图标尺寸为 96dp，足够清晰且体积可控（几百个 App 约占几～十几 MB 存储）。
- 关闭「启用 APP Dialer 缓存」开关后，恢复为纯实时读取（永远最新，但每次打开需重新扫描，较慢）——这是预期行为。
